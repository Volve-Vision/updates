# VolveMenu

**[menu.volvevision.com](https://menu.volvevision.com)** - digital menu boards for cafes, bars and
retail. A screen on the wall, a phone in the owner's pocket, and nothing in between.

Built in August 2026. The service runs in production and the management app is published on the
App Store and Google Play. It is running on trial screens with people we know. No commercial
venue is using it yet.

---

## What it does

- A venue owner builds a menu on their phone and it appears on the screen in the room.
- Screens pair with a short code. No account setup on the screen itself.
- Menus keep working when the internet does not: everything a screen needs is stored locally, and
  it catches up when the connection returns.
- Several screen formats, each with its own templates, including video and still layouts.
- Multiple screens per venue, each showing its own menu, reassigned as the venue changes.
- Prices are optional per template, because not every screen is a price list.
- A shareable read-only view, so a menu can be sent to someone without giving them access.
- Every new account starts with finished demo menus, so the product is never empty on first open.
- A web workspace for running the venue from a computer, alongside the phone app.
- Guests order from the table and leave ratings; orders reach the staff with the table number.
- Schedules, timed promotions, chains of venues and team roles with owner approval.

## History

### October 2026

The web workspace and help centre are live. The management app changes are in version 1.1, submitted
to App Store review and not yet released; the Android build is not yet in Google Play.

- **Added** a web workspace, signed in by scanning a code with the phone app.
- **Added** one catalogue of dishes per venue, used by every menu, in six languages, with
  spreadsheet and point-of-sale import, a check before changes and a one-step undo.
- **Added** guest ordering from table tablets and per-table codes, with the table number on every order.
- **Added** guest ratings and comments.
- **Added** scheduled menus by time and weather, timed promotions and an urgent message on every screen.
- **Added** chains of venues with shared menus and their own prices and stop lists.
- **Added** team roles, with owner approval of changes made by managers.
- **Added** a report of what each screen actually displayed.
- **Added** a help centre for owners.
- **Added** an overview page with setup steps for a new venue and today at a glance for every venue.
- **Added** a search box that finds sections, dishes, menus, screens and common tasks.
- **Changed** empty sections explain what belongs there and offer the next step; sections show a short hint on the first visit.

### September 2026

The Android permission change is in the published Google Play build. The other items below are
complete but are not yet in a store build.

- **Added** the account security centre to the management app, matching the website and the main
  mobile app.
- **Changed** session handling so a wall-mounted screen is never signed out by accident.
- **Fixed** a support link that failed in languages the website does not serve.
- **Changed** the Android build to request only the permissions it actually needs.

### August 2026

The whole product, in one month:

- **Added** the service behind it: venues, menus, screen pairing, offline delivery and
  real-time updates.
- **Added** the management app for iOS and Android.
- **Added** media handling, so a video uploaded from a phone plays correctly on a large screen.
- **Added** instant pairing feedback: the screen reacts the moment it is claimed or released.
- **Added** push notifications to the owner's iPhone, including when the app is closed.
- **Added** menu duplication, per-format menus, thumbnails and screen counts.
- **Added** on-demand screen snapshots, so an owner can see what a screen is showing right now.
- **Added** a public read-only view behind a share link.
- **Added** demo content that every new account gets its own copy of.
